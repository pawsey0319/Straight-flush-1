# 可提交 Demo 可行性规划

## 目标

在 24 小时限制内交付一条可访问、可操作、可解释的主链路，覆盖题目要求的自然语言澄清、结构化条件、冲突与数据质量状态、确定性筛选、证据解释、条件影响分析以及保存/监控入口。

## 首版范围

### P0：必须在 Demo 中跑通

1. 输入“找经营改善、估值合理、走势相对稳定的 A 股”。
2. 识别三个语义概念，说明含义并展示定义候选。
3. 用户确认增长型、绝对估值、波动率口径。
4. 展示结构化条件、来源和单位，并支持修改阈值。
5. 展示硬冲突校验结果和 `unknown` 数据状态规则。
6. 执行固定演示快照，返回入选、排除和未知结果。
7. 查看单只股票的通过/失败/未知原因、实际值、阈值、来源和时点。
8. 修改条件后展示候选数量变化和被移除标的。
9. 保留策略保存、版本、回测和监控入口，并说明当前 Demo 的边界。

### P1：接入真实数据后的增强

- 封装扶摇与 iFinD `MarketDataProvider`，前端只调用后端。
- 使用真实字段和原始响应写入证据账本。
- 加入 SQLite/PostgreSQL 保存策略、运行记录和用户确认的口径记忆。
- 接入历史快照后实现防未来信息的最小回测。
- 使用定时任务执行监控并发送数据质量告警。

## 页面与交互编排

| 页面区域 | 演示动作 | 评审能看到的价值 |
|---|---|---|
| 自然语言输入 | 重新解析示例意图 | 不是只展示一张结果表，而是从意图开始 |
| 语义澄清 | 切换定义型卡片 | AI 不擅自补指标和阈值 |
| 策略条件 | 编辑数值条件 | 条件可检查、可修改、可追溯 |
| 结果摘要 | 入选/排除/未知 | 缺失数据不被静默当作失败或通过 |
| 证据账本 | 点击股票查看详情 | 每个结论都能回到字段、时点和来源 |
| What-if | 修改利润门槛 | 条件变化带来的集合变化可解释 |
| 下一步 | 保存、回测、监控入口 | 筛选结果可进入持续使用流程 |

## 24 小时安排

| 时间 | 工作 | 产出 |
|---|---|---|
| 0–2 小时 | 冻结主链路、状态枚举、页面线框 | `Strategy IR`、数据契约、演示脚本 |
| 2–6 小时 | 搭建静态 Web 与演示数据适配结构 | 页面骨架、固定快照、基础样式 |
| 6–10 小时 | 实现澄清卡、条件编辑器、冲突提示 | 语义层与执行层边界 |
| 10–15 小时 | 实现结果表、证据抽屉、结果状态 | 入选/排除/未知解释 |
| 15–18 小时 | 实现 What-if、保存、监控与回测入口 | 结果后续动作 |
| 18–21 小时 | 注入缺失、超时、窗口不足场景并测试 | 异常与合规验证记录 |
| 21–24 小时 | 部署 GitHub Pages、整理 README 与文档 | URL、仓库、交付材料 |

## 提交策略

Demo 采用静态单页发布，降低部署风险；源码中保留数据适配层的字段契约和真实接入说明。演示数据只用于产品体验，README 和页面都明确标注快照时间与边界。最终提交时提供 GitHub Pages URL、源码仓库、README、AI 使用记录、测试报告和本规划文档。
