# AI 使用与验证记录

## 使用环节

本次 Demo 使用 AI 辅助完成：

1. 从题目和初版方案中提取 MVP 范围、状态机和交付清单。
2. 将“经营改善、估值合理、走势相对稳定”拆为语义意图和定义候选。
3. 设计页面信息架构、演示脚本和可追溯证据结构。
4. 生成静态 Demo 的页面骨架、样式和交互代码。
5. 按交付要求编写 README、架构、规划和测试记录。

## 人工检查与修正

| 检查项 | AI 初始建议 | 人工确认/修正 |
|---|---|---|
| 模糊概念处理 | 可能直接生成指标阈值 | 改为先展示定义候选，只有用户确认后才进入条件 |
| 数据缺失 | 可作为空值继续计算 | 改为统一显示 `unknown`，禁止静默通过或失败 |
| 解释数字 | 可由模型直接组织自然语言 | 改为模板先绑定证据，模型只能润色表达 |
| 回测 | 可展示历史收益曲线 | 因没有真实历史快照，保留入口并明确未伪造收益 |
| 投资建议 | 可根据入选结果给出建议 | 删除买卖建议、收益承诺和确定性涨跌预测 |
| 数据来源 | 可用演示值快速搭建 | 页面和 README 标注为演示快照，不冒充实时数据 |

## 验证结论

- 页面主链路可以从自然语言输入进入条件确认，再进入结果解释。
- 执行层条件均显示 `user_confirmed`，没有将 `ai_inferred` 当作可执行来源。
- 结果列表包含入选、排除和未知三类状态。
- 关键事实包含实际值、阈值、单位、来源和时点字段。
- 合规边界在页面底部和说明弹窗中可见。

## 后续 AI 接入要求

如果接入真实 LLM，必须要求结构化 JSON 输出，并在服务端做 Schema 校验。模型输出不能直接作为 SQL、Python 或筛选 AST 执行；解释模型只接收确定性引擎输出的证据摘要。
