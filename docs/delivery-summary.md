# 聊天记录与交付要求总结

## 1. 用户目标

用户要求：读取题目文件和初版方案，编排一份可行的 Demo 规划，并最终提交可访问操作的 Web 产品 URL、源码和 README 到 GitHub 仓库 `pawsey0319/Straight-flush-1`；同时把本次聊天中形成的判断、边界和执行计划整理成符合题目要求的文档。

## 2. 依据材料

- `02_自然语言智能选股与策略解释器.md`：题目、提交要求、数据源和统一规则。
- `初版方案-自然语言智能选股与策略解释器.md`：MVP 主链路、Strategy IR、三层职责、异常处理、测试矩阵和演示脚本。

## 3. 已确定的执行计划

1. 冻结“自然语言 → 澄清 → 条件 → 校验 → 筛选 → 解释 → What-if → 保存/监控”的主链路。
2. 以静态 Web 先交付稳定可访问的产品体验，避免在 24 小时限制内被后端部署阻塞。
3. 将 AI、确定性筛选引擎和数据适配层分开描述，禁止 AI 直接执行未经校验的查询。
4. 用 `pass / fail / unknown` 表达结果，缺失、过期、接口失败和窗口不足均不得静默通过。
5. 用页面、README 和文档明确演示数据快照边界，真实数据接入保留字段契约和 provider adapter 方向。
6. 完成 GitHub Pages 发布、源码仓库、README、AI 使用记录和测试说明。

## 5. 评审演示口径

演示输入使用：`找经营改善、估值合理、走势相对稳定的 A 股。`

演示重点依次展示：

1. 系统识别三类语义，不自动替用户补阈值。
2. 用户确认定义和条件后再运行筛选。
3. 入选、排除、未知结果分别解释。
4. 点击单只股票查看证据账本。
5. 修改利润门槛，展示候选集合差异。
6. 保存策略、回测、监控入口和合规提示。

## 6. 尚未承诺的内容

当前提交是可操作 Demo，固定数据用于验证产品主链路。真实扶摇/iFinD 接口、在线 LLM、服务端存储、真实历史回测和定时监控需要后续配置接口权限、部署后端和真实数据快照后接入；在此之前不把演示数据包装成实时金融数据，也不伪造收益结果。
